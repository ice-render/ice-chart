## 1. 两族组件与「盒」

| 族 | 盒 | 本地坐标 | 例子 |
|---|---|---|---|
| **系列** | 绘图区矩形（极坐标是圆的外接正方形） | 绘图区内的像素（`0..plot.width` / `0..plot.height`） | 所有 `components/series/*` |
| **覆盖层 / 网格** | 整块画布 | 就是画布坐标（不减 `plot`） | `Axis` / `GridLines` / `Legend` / `Title` / `Tooltip` / `Crosshair` / `DataZoomSlider` |

两处最容易踩的坐标坑：

1. **比例尺 `map()` 返回的是绘图区本地坐标**：覆盖层要用它必须先加 `plot.x/plot.y`；
   系列组件的盒本来就是绘图区，所以反而**不用**加。
2. 多减一次 / 少加一次都表现为「整块画到别处」：雷达网格多减了一次 `plot` → 整张网格跑到左上角；
   极坐标网格忘了加 → 画到绘图区外面。

引擎图元的 `left/top` 是绘制盒左上角，`origin` 只影响变换枢轴 —— 摆位时不要再按 `origin` 做中心换算。

## 2. 像素缓存：唯一来源

**契约**：`rebuildPixels()` 是点集像素的**唯一**来源，渲染与命中都消费 `this.pixels`。

```ts
class SeriesBase {
  pixels: Float64Array;        // [x0,y0, x1,y1, …] 绘图区本地坐标
  effective: Float64Array;     // 动画插值后的 base/top（每点两个值）
  itemProgress: Float64Array;  // 每个数据点自己的进度（错峰动画）
  protected rebuildPixels(force = false): void;  // 带缓存
  public pixelAt(index): [number, number] | null;
}
```

三条纪律：

1. **缓存键走 `this.buildSeriesKey([...几何参数])`**。它自动拼上：
   `coordKey()`（绘图区矩形 + 两个比例尺的**域端点与长度**）、`progress()`、动画阶段、错峰参数。
   - 漏掉 `progress` → 动画只动第一帧之后冻住；
   - 漏掉坐标系指纹 → 缩放 / 平移 / 域过渡后 `pixels` 停在旧位置，
     「画出来的点」与「点得到的点」分叉（表现为悬停高亮画在别处）。
2. **平移走增量**：域只平移（跨度没变、两轴都是数值）时给每个点加一个常数，不必重跑
   `map()` / `computeEffective()` / 抽样；缩放与换数据仍全量重算。
3. **惰性原始点是唯一例外**（`series.raw`）：它照旧建像素缓存，因为自定义系列的
   `doRender()` 通常直接读 `this.pixels`；数值列 / 矩阵才连像素一起省。

## 3. 命中判定就在组件里

`SeriesBase.containsLocalPoint(lx, ly)` 的实现就是 `hitTestIndex(lx, ly) >= 0`：

- 遮挡关系、`zIndex`、`display:false`、`interactive:false` 全部由引擎统一保证；
- 图表层**不许**另写一套「坐标反查数据」，那必然与渲染漂移。

大点数的命中都不许 O(n) 扫：

| 类型 | 命中方式 |
|---|---|
| 折线 | 单调 x 上二分找锚点 → 邻域 ±2 比标记 → 邻域 ±1 比线段距离 |
| 散点 | 同上（虚拟系列从列现算像素） |
| 柱子 | 稠密模式（类目轴 + 每像素 > 2 根）按 x 比例反推下标，再验邻域 2 根 |
| 热力图（矩阵） | 类目查表 + 下标运算（O(1)） |

小点数（约 1k 以下）仍走全量扫描，语义与二分分支一致（有回归用例盯着）。

## 4. 绘制纪律

1. **`doRender()` 必须自己 `ctx.beginPath()`**：引擎的脏矩形局部重绘会在 ctx 上留下
   clip 用的 rect 路径，直接 `stroke()` 会把那条残留路径一起描出来（画布边缘莫名多一圈线）。
2. **直角坐标系列必须 `clipToBox = true`**：缩放后窗口外的点会被线性外推到画布之外，
   不裁剪就会盖住坐标轴与图例。折线要的是「被绘图区边缘裁掉」，不是「在边界处断开」。
3. **`style` 的键名是 ctx 属性名**（`fillStyle` / `strokeStyle` / `lineWidth`），
   `fill` / `stroke` 是「要不要填充 / 描边」的布尔。
   写成 `style: { fill: '#f00' }` 会把 ctx 的 `fill()` 方法覆盖成字符串，运行时炸。
4. **改了 `ctx.textAlign` / `textBaseline` 的分支必须显式还原**：逐元素循环里最容易漏，
   表现为「后面的标签整体右移半个字宽」（宽块看不出来、窄块把字顶出画布）。
5. **渐变只在看得见的时候建**：柱子高度 < 3 设备像素时用纯色（1M 根时每根一个渐变实测 180ms/帧）。

## 5. 密度策略：亚像素下不逐根画

远景（一屏几千根以上）时图元的物理尺寸小于 1 像素，「逐根画」既白烧 CPU 也是无效像素。
统一口径：**按像素列聚合 / 抽样，落墨量与像素数同级；命中与提示框仍走全量数据**。

| 类型 | 规则 | 实现 |
|---|---|---|
| 散点 | 每像素列约 2 点（`stride`） | `ScatterSeries` 的密度抽稀（虚拟 / 普通同规则） |
| 折线 / 面积 | 每像素列最多 4 个点（首 / 最低 / 最高 / 末），每列 ≤ 8 个候选 | `LineSeries.virtualRenderSequence`；普通系列走 LTTB |
| 柱子 | 每像素列一根**聚合矩形**（该列 `[min(base,值), max(base,值)]` 的并集） | `BarSeries.drawDense` |
| 热力图（矩阵） | 按**屏幕像素块**聚合，块内取最大值（热点不被抹平） | `HeatmapSeries` 的矩阵路径 |

配套三条纪律：

1. **稠密模式不建「每根一个」的像素缓存**（1M 根柱子 `rebuildPixels` 要 5.6ms/帧，而稠密绘制根本不用它）。
2. **对比度靠聚合、不靠抽样掉极值**：「折线丢极值就是撒谎」，所以每列保留首 / 最低 / 最高 / 末。
3. **普通折线的取点策略不要再折腾**：同一份数据、同一张画布，10 万点真滑窗实测
   **LTTB 61ms / 帧、按像素列聚合 124ms、只画极值 149ms** —— LTTB 已经是最快的。

## 6. 动画

1. **三段式配置**：`option.animation.enter / update / highlight`（扁平写法等价于 `enter`）。
2. **错峰靠「每项自己的进度」**：`SeriesBase.itemProgress` / `progressFor()`，
   不为每个数据点建组件（组件数会爆）。
3. **域过渡**：更新时 y 轴数据域常变，必须与值一起插值（`ICEChart.domainTransition`），
   过渡期间同步组件传 `preserveAnimation = true`（只换 series 引用，不清 `fromEffective`）。
   **只对直角坐标启动**：极坐标 / 雷达 / 仪表 / 水位 / 树图不按 y 轴排布，
   启动过渡只会每帧全量重建，而且因为 `setData` 会重置进度，过渡**永远到不了终点**。
4. **跟手的东西（准星 / 游标类覆盖层）不许用固定时长补间**：指针是连续输入，
   每次 mousemove 重置目标 → 固定时长补间被反复重启，实测滞后 50~300px、数据流页面甚至不收敛。
   正确做法是**按距离给时长**（约 5px/ms，上限 90ms），小位移当帧落位。
5. **`finishAnimations()` 只收尾一次性补间**：`__` 前缀的是循环补间（蚂蚁线 / 流动 / 水位波浪），
   收尾会永久冻住它们；同时要把 `props.animations[*].finished = true` 并摘出 AnimationManager，
   否则下一帧引擎又把进度写回去。
6. **动效偏好是产品能力**：`setMotionPreference('auto' | 'instant' | 'full')`，
   `auto` 跟随 `prefers-reduced-motion`；测试环境全局设 `instant`（断言确定、跑得快）。

## 7. 覆盖层与浮层

1. **交互反馈用独立覆盖层**（`Highlight` / `Crosshair` / `Tooltip`），鼠标移动只让它们变脏，
   **不重绘系列**；压暗其他系列只在「悬停系列变化」时写一次 state。
2. **落在画布上的控件要走独立实例**：`ice-chart` 内部自己 `new ICE()`，不接受外部实例；
   要在图上盖控件就另起一块 canvas（宿主页的控件条就是这么做的），
   并注意 `isOverCanvas()` 会把指针判给「面积上真正的那张图」。
3. **数据坐标图元**（`chart.addMark(...)`）挂在独立的 `markLayer` 上，随比例尺摆动
   （`syncMarks()`）；拖拽时交互要给图元让路（见 `04-interaction.md` §7）。

## 8. 视觉硬约束

这些约束由 `scripts/audit-interactions.mjs` 逐步断言（30 个示例页、300+ 步）：

1. 提示框 / 准星标签**不越出画布**，**不压坐标轴标签与图例**。
2. 高亮必须在**绘图区内**，饱和色墨迹不许跑到坐标轴带上。
3. 「放得下才画」必须用 `measureTextWidth` 量**真实文本宽度**，不能只按矩形尺寸猜。
4. 轴文字与轴名称必须是**近灰**（审计用「通道极差 > 45 视为饱和墨迹」判断越界）。
5. 新增示例页 / 新增交互能力时，同步给审计脚本加一步 —— 否则这个门禁覆盖不到。
