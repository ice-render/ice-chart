## 1. 事件入口

引擎的原生监听挂在 **window** 上：同一页面上的每张图都会收到**整页**的事件。
因此每个指针入口的第一句都是「这次事件属不属于我」：

```
handlePointerMove(x, y)
  ├─ 正在拖拽？→ updateDrag 并返回
  ├─ !isOverCanvas(x, y) → 只收自己放上去的悬停（externalHover 不收），然后返回
  └─ updateHover(x, y)
```

两个必须牢记的点：

1. **画布量不到尺寸（`canvasWidth/Height` 为 0）＝ 指针不在本图上**，判 `false`。
   被 `display:none` 藏起来的图尺寸为 0，早先这里返回 `true`（「尺寸未知就当指针在上面」），
   于是隐藏中的图把全页移动都吃下来、在错误坐标上锁住一个悬停；等它显示出来，
   `refreshHover()` 把陈旧悬停重新解析一遍 —— 画面上凭空多出一个**擦不掉的提示框**。
2. **指针离开画布要主动 `setHover(null)`**，不能只是「忽略这次事件」：
   画布外不再产生让本图重新取悬停的坐标，只 `return` 的话提示框会一直挂着。

坐标换算用的是引擎缓存的 canvas 内容盒；引擎 1.4.5 起移动事件每帧重读（`ICE.refreshInputRect()`），
当前 peer 依赖 `^1.4.7`。在那之前**不要把会产生布局变化的面板放在画布上方**
（示例页踩过：状态行出现后画布下推 26px，悬停直接落空）。

## 2. 命中解析链

`HitResolver` 负责「像素 → 组件 → 数据下标」：

1. `resolveTarget(x, y)`：先问引擎 `ice.hitTest()`（谁是顶层命中组件），拿到组件与本地坐标；
2. `seriesOfComponent(component)`：组件 → `InternalSeries`（有 id 兜底，
   因为 `rebuild()` 每次都重建 norm，悬停里存的是**上一轮**的系列对象）；
3. `buildActiveItem(series, index)`：数据下标 → `ActiveItem`（含 `point` / `pixel` / 颜色 / 系列元信息）；
4. `pickColumn(chartX)`：`trigger: 'axis'` 时按 x 值取**整列**（多系列同列一起展示）。

两条要点：

- **`containsLocalPoint` 就是数据命中判定**（见 `rendering.md` §3）：解析链只做「组件 → 数据」的翻译，
  不重算几何。
- **`nearestIndexByX` 走组件自己的 `nearestIndexAtX`**：单调序列二分、非单调退化为线性扫描，
  语义与像素缓存版一致。

## 3. 悬停的三条铁律

1. **尺寸为 0 判不在**（见 §1.1）。
2. **离开画布主动清悬停**（见 §1.2）。
3. **指针只能收自己放上去的悬停**（`controller.externalHover`）：
   `showHoverAtValue()` / 联动回显放上来的悬停，由**放它的那一方**收回。
   上面第 1 条说明一次 mousemove 会派发到整页每一张图：被联动**回显**出悬停的图本身并没有指针悬停，
   它若按「指针不在我身上」把回显删掉 —— 多 pane 的十字准星就永远做不出来。

配套的还有两类状态陷阱：

- **悬停状态里的系列对象会过期**：`rebuild()` 每次重建 norm；`HitResolver.seriesComponentOf()`
  有 id 兜底、`refreshHover()` 从当前 norm 取新系列 —— 否则「数据更新时悬停被清掉」
  （实时刷新的仪表盘 1.6s 掉一次，肉眼可见）。
- **`refreshHover()` 不要按「场景类型」提前清空悬停**：非直角坐标（雷达 / 饼图）也可能出现
  `axis` 悬停（同一指标 / 同一切片下标的对比有意义）；只有直角坐标才做「列像素是否还在绘图区内」的检查。

## 4. 缩放与平移

### 4.1 缩放口径是「每根多少像素」

`interaction.zoom.minBarSpacing`（默认 0.5px/根）/ `maxBarSpacing`（默认 0 = 自动 → 绘图区宽度的一半
等价「一屏最少两根」），实现在 `util/zoomLimit.ts`。

**为什么不能用「占数据域的百分之几」**：那个比例会随图上载入了多少根漂移
（实测缩到底到过 0.24px/根，一根占不到一个像素，整片糊成色带）。

限制**只约束手势缩放**（`source === 'zoom' | 'brush'`）：程序化 `setDomain` 与联动回显
（`source: 'api' | 'link'`）不受限 —— 「回到最新」钉最后 count 根必须指哪打哪，联动要两张图窗口严格一致。

### 4.2 平移的两条口径

1. **符号**：x 轴「值越大越靠右」与屏幕同向，用 `-deltaPixels`；y 轴「值越大越靠上」与屏幕**反向**，
   必须用 `+deltaPixels`（同一个符号会让纵向拖动方向整个反过来）。
2. **平移不许和数据范围求交**（那是给缩放用的 `clampAxisDomain`）：平移这么做会把窗口一端夹住、
   另一端继续走 —— **平移被悄悄退化成缩放**（实测纵向拖 120px，量程从 `[41100,41700]` 变成
   `[41100,41449]`）。现在 `source === 'pan'` 单独走：保住跨度，只要求与数据范围至少交叠 1/4 个窗口。

### 4.3 类目轴的「窗口」是首尾两个类目

`norm.xAxis.domain` 对类目轴是**窗口内的整串类目**（窗口里 120 根就是 120 项），
只有连续轴才是 `[min, max]` 两项。平移取窗口与位移计算都必须按这个来，
否则「能上下拖、不能左右拖」（非常容易误判成配置问题）。

窗口越出数据时要「**贴边滑**」：一端越界 → 整窗贴数据边缘滑、**跨度保持不变**；
两端都越界（这张图表达不出来）→ **保持原窗口**，宁可这一帧不动，也不能跳到整段。

### 4.4 交互窗口的兜底

用户手势产生的窗口必须**至少盖住 2 个数据点**（类目轴至少 2 个类目；数据只有 2 个点时放宽到 1 个），
否则窗口可能落进取整出来的空白区，可视点 0 个、整条曲线消失（用户描述为「缩成一团」）。
兜底只作用于用户手势；`setDomainFromFractions()` 这类**公共映射函数保持精确**（用 `guard` 参数区分）。

## 5. 框选、键盘、图例与扇区

1. **框选**（`Brush`）：`interaction.brush` 配置，`axes: 'x' | 'y' | 'xy'`；
   按下处理必须在命中图元时**提前返回**，否则「拖注释」会变成「框选 / 平移抢走拖拽」。
2. **键盘**：只由**最后激活的图**响应（模块级 `activeController`，`destroy()` 时释放）；
   不要在 `keydown` 里对所有图生效。
3. **图例**：`Legend` 的 hover / 选中态自己维护；悬停图例时只清数据层视觉，
   **不要顺手重置图例自身的悬停高亮**。
4. **显隐切换是动画不是瞬跳**：`toggleSeries` / `toggleSlice` 传 `animate: true`；
   饼图用 `sliceFrom`、漏斗用 `stageFrom`，都按数据下标对齐。
   **对同一批刻度做过渡时插值「起点 + 扫过角」**，不要分别插值两个端点 ——
   饼图隐藏扇区时端点各自走最短路径，会让扇形中途先变宽再收拢（看起来像抖了一下）。

## 6. 跨图联动

`linkCharts(charts, { axis })` 的语义与纪律：

1. **回显必须包 `silent()`**：把事件转发给其它图时必须静音，否则 A→B→A 无限递归
   （`RangeError: Maximum call stack size exceeded`）。
2. **回显之死不是「离开」**：只有源头图自己发的 `item:leave` 才许清别人；
   被联动图在同一次 mousemove 里丢掉回显的话，跨 pane 的十字准星根本做不出来。
3. **窗口对齐走比例**：不同轴类型的图用 `fractionOf` / `setDomainFromFractions` 对齐，
   不做值域直译。

## 7. 图元交互要让路

`chart.addMark(spec)` 造的图元（数据坐标）与注释拖拽属于「用户直接操作的东西」：

1. `InteractionController` 的按下处理**命中图元就提前返回**，把拖拽让给图元；
2. 拖拽过程中**不要**触发框选 / 平移；结束用 `finishMarkDrag()` 收口；
3. 图元位置随比例尺摆动（`syncMarks()`），缩放平移后不脱锚。

## 8. 反馈的性能纪律

1. **悬停反馈用独立覆盖层**：鼠标移动只让 `Highlight` / `Crosshair` / `Tooltip` 变脏，**不重绘系列**。
2. **压暗其他系列只在「悬停系列变化」时写一次 state**：每次 mousemove 写系列 state 会让脏矩形失效。
3. **准星 / 游标按距离给时长**（见 `rendering.md` §6.4），不要用固定时长补间。
4. **悬停要能探测到「真的画出来了」**：断言 `hoverIndex` 只说明状态对了，
   交互用例要断言 `barDrawRectAt()` / `highlightRectAt()` / `panelOpacity()` 这类**真正参与绘制**的值。
