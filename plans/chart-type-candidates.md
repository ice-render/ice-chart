# 图表类型候选：数据型图的方向（§4.2 已落地，其余待定）

> 状态（2026-09-24）：调研完成；**§4.2 分布组图已落地**（`violin` / `beeswarm`，
> 见 `CHANGELOG.md` 的 Unreleased、「示例页 `examples/distribution.html`」），其余候选仍未开工。
> 本文回答两件事：① 哪些形态该由本库做、哪些已经有人做了（§2）；
> ② 如果要做，先做哪几个、怎么落（§4 / §6）。
> 新会话从这里读，不要重新调研；定了做哪个，再把对应小节扩成施工图。
>
> 起因：想在「类型清单」上找空档，做别的库不方便做的类型。
> 核对后的结论是：**通用类型基本都被产品化了，按类型数量堆冷门类型收益很低**；
> 空档集中在**统计分布族**与**多面板族**，而真正的差异化在
> 「几何形态 × 规模 × 语义交互」的交集上 —— 哪些图不只好看，还要
> **十万个图元逐个可命中 + 跨面板联动 + 能每帧重算**。

## 1. 结论先行

1. 通用类型（折线到桑基、树图、旭日、主题河流、日历、平行坐标、误差棒…）已有成熟实现，
   补进去只是追平，不构成卖点。**类型清单不是战场。**
2. 值得做的是下面这类形态：单点可命中、可联动、还要规模 —— 正好压在本库已有的四条能力上
   （列存 / 脏矩形像素契约 / `containsLocalPoint` 即数据判定 / 单画布多面板 + 画布内提示框 + 跨图联动）。
3. **建议先做**：小倍数 + 边际分布 → 分布组图 → 六边形分箱（§4）。
4. 科学数值向（等值线 / 流场 / 相图 / 域着色）**不进核心库**，理由与归属见 §5。

## 2. 家族边界（判据）

一句话：**用户画出来的图归 `ice-entity-designer`，数据变出来的图归 `ice-chart`。**

| | 文档型图 | 数据型图 |
|---|---|---|
| 典型 | ER / 流程图 / BPMN / UML / 状态机 / 甘特 / 电力一次二次 / 给排水 | 折线 / 柱 / 散点 / 热力 / 桑基 / 分布 / 分面 / 日历 |
| 归属 | `ice-entity-designer` 域包 | `ice-chart` |
| 判据 | 用户创作、可编辑、有语义校验、有标准互操作格式 | 只读视图、形态由数据与 option 决定、改了数据图就变 |

桑基 / 关系图 / 树图落在中间地带，但定位已经清楚：本库这几个是**由数据算布局**的只读视图
（分层松弛 / 力导向 / squarified），用户不编辑节点语义，所以不冲突。

### 2.1 已知重复（不要再做）

| 条目 | 已归属 | 证据 |
|---|---|---|
| 甘特 / 排期（泳道 + 依赖线 + 拖拽改期） | `ice-entity-designer` | `src/gantt/`：时间轴 + 按天吸附 + 依赖线 + 自动排程 + 关键路径 + 资源冲突校验 + Mermaid 互操作 + 矢量导出 |
| 可编辑图表族（拖动图元回写数据） | `ice-entity-designer` | 它的正职就是「创建 / 更新 / 删除 / 连线 / 撤销重做 / 快照 / 语义校验」这套交互闭环。`option.annotation` 与 `addMark()` 的拖拽继续服务标注场景，但**不再扩成产品方向** |
| 节点 + 连线 + 语义校验的建模图 | `ice-entity-designer` 域包 | 同上，9 个域包已覆盖 |
| K 线 / 交易语义 | `ice-trading-chart` | 独立包挂在本库之上，本库不知道交易存在 |

## 3. 我们凭什么做（既有杠杆）

| 杠杆 | 出处 | 换来的形态 |
|---|---|---|
| 任意形状即命中区 | `SeriesBase.containsLocalPoint`（`src/components/series/SeriesBase.ts`），命中判定就是数据判定 | 不规则的统计图形（密度轮廓、碰撞后的点、弧带） |
| 列存 / 虚拟子源 | `docs/10-column-store-virtual-series.md`：100 万点堆 2.2MB、命中 0.00ms；1000×1000 热力矩阵堆 3.3MB、命中 O(1) | 十万级点仍逐点可命中的分布图、六边形分箱 |
| 脏矩形像素契约 | `docs/03-rendering.md` | 每帧重算的形态（抖动展开、粒子流），不必全量重绘 |
| 单画布多面板 + 画布内提示框 + 联动 | `ChartLink` / `InteractionController.buildTooltipContent` | 小倍数、边际分布 |
| 归一化与布局是纯函数 | `option/normalize.ts` / `layout/*` | KDE、分箱、碰撞布局都能单测，不依赖 DOM |

## 4. A 档候选（建议做）

成本口径：**估算是工作量档，不是实测**；「组件 + 归一化分支 + 三类测试 + 示例页 + DSL 同步」
是每个类型的固定盘子（见 §6），档位只反映多出来的布局 / 数值核。

### 4.1 小倍数（分面）+ 边际分布（joint plot）

> **✅ 小倍数已落地（2026-09-24，分支 `feat/small-multiples`）**：`option.matrix` + `series[].panel`、
> 每面板一套比例尺（域共享）、轴只画外圈、交互按指针所在面板解析。
> 设计见 `docs/superpowers/specs/2026-09-24-small-multiples-matrix-design.md`，
> 机制与纪律见 `docs/06-chart-types.md` §8 与根 `AGENTS.md` 的「面板矩阵」一节。
> **边际分布仍未做**：几何已由 `columns: [4, 1]` 的权重给到，还差面板级轴可见性与边缘面板绑第二个 y 轴。

- **形态**：一张画布上 N 个同构面板，共享比例尺（或按需各自独立），共享十字线与框选；
  边际分布 = 主图（散点 / 热力）+ 轴侧直方图 / 密度，是分面的特例。
- **为什么别人做起来难受**：一个实例一个坐标系，做 N 个面板要 N 个实例，再手工同步悬停、
  缩放、框选；提示框若是 HTML 浮层，跨面板定位会飘。
- **我们怎么做**：布局层切分面板矩形（`layout/layout.ts` 旁边加一个纯函数），
  复用现有系列组件；联动走 `ChartLink` 的既有语义；提示框本来就在画布内。
  轴只画外圈、网格按配置对齐。
- **成本**：中。无新几何，主要风险在 option 形态（§8）与轴标签空间分配。
- **验收**：≥ 6 面板 × 1 万点，悬停 / 框选 / 缩放三件事在所有面板同时生效，
  单帧重绘不超过一个面板的脏矩形（用 `scripts/measure-pipeline.mjs` 同款口径量）。

### 4.2 分布组图：小提琴 + 蜂群 + 箱线（雨云图）

> **✅ 已落地（2026-09-24，分支 `feat/distribution-series`）**：`violin` / `beeswarm` 两个内置类型
> + 纯函数 `src/layout/density.ts`（`computeKdeProfile` / `computeBeeswarmOffsets` / `silvermanBandwidth`）
> + 示例页 `examples/distribution.html`。实现口径与坑记在 `docs/06-chart-types.md` §2.1 与
> `AGENTS.md` 的「分布组图」一节。下面保留当初的设计与验收口径，便于对照。

- **形态**：类目轴上按组展示分布。小提琴 = 核密度轮廓（可半宽、可镜像）；
  蜂群 = 点在类目轴上有碰撞避让的排布；箱线已有（`BoxplotSeries`），组合起来就是雨云图。
- **为什么别人做起来难受**：主流实现里这类统计形态要么没有、要么只在社区插件里；
  点一多就必须退化成「密度转色块」，逐个点不再可命中。
- **我们怎么做**：
  - KDE 与带宽是纯函数，放 `option/normalize.ts` 或新的 `layout/density.ts`，可单测；
  - 蜂群碰撞按**像素列分桶 + 每列内二分插入**，O(n log n)，不物化两两距离；
  - 命中：小提琴按与渲染共用的轮廓折线判定；蜂群按像素列找最近点；
  - 列存形态复用 `docs/10` 的路径，用于十万级点；
  - 抖动展开动画走引擎 `AnimationManager`，脏矩形保证只重绘本系列。
- **成本**：中。几何不难，难在带宽选择要可配 + 极端分布的诊断（与表达式诊断同风格：
  **诊断只挂数据，不让图表抛异常**）。
- **验收**：20 组 × 5000 点，蜂群布局 < 16ms，命中 < 1ms，
  tooltip 给组名 / 观测数 / 分位数 / 密度峰值；列存形态不进快照的代价要写清。

### 4.3 六边形分箱（hexbin）

> **✅ 已落地（2026-09-25，0.30.14）**：像素空间分格 + O(1) 命中，交互单位是格子。
> 见 `docs/06-chart-types.md` §2.2 与 `examples/hexbin.html`。

- **形态**：点云在六边形格上聚合，用色阶显示计数或聚合值；与热力图互补（六边形无方向偏置）。
- **为什么别人做起来难受**：多数库没有，要用户自己算格子；有了格子又常常丢命中。
- **我们怎么做**：与已落地的**列存矩阵**同族 —— 格点寻址是 O(1) 的坐标变换，
  命中不需要遍历；亚像素聚合与「热点取最大值」直接复用热力的既定策略。
- **成本**：低-中（`HeatmapSeries` 旁边一个新组件 + 归一化分支）。
- **验收**：100 万点入箱 < 60ms，命中 O(1)，缩放后按屏幕像素重聚合不出现摩尔纹。

### 4.4 多轴分类流（平行集 / alluvial）

> **✅ 已落地（2026-09-25，0.30.16）**：表的分面（`alluvial: { axes, rows }`）+ 重心排序 + 节点/带子分别命中。
> 见 `docs/06-chart-types.md` §2.3 与 `examples/alluvial.html`。

- **形态**：N 个类目轴并列，相邻轴之间用带（ribbon）表达流量；带可堆叠、可高亮整条路径。
- **为什么别人做起来难受**：这是分类数据的「多级桑基」，主流实现要么只有两三级，
  要么把轴固定死，改轴数就要重写布局。
- **我们怎么做**：`layout/sankey.ts` 已与渲染解耦 —— 扩成「N 轴 + 每轴排序 + 相邻轴之间一段桑基」，
  几何与命中都复用现成的节点 / 连线判定与「连线按宽度着色」策略。
- **成本**：中。风险在轴的排序策略（默认按量、可传自定义序）与带交叉时的可读性。
- **验收**：4 轴 × 每轴 12 类目，悬停一条路径时两端轴段与中间带同时高亮，命中 < 1ms。

### 4.5 日历热力（含小倍数形态）

> **✅ 已落地（2026-09-25，0.30.16）**：UTC 日期语义 + 反解命中 + 月份/星期标签。
> 见 `docs/06-chart-types.md` §2.3 与 `examples/calendar.html`。

- **形态**：按日期排布的热力格，可跨年平铺、可按星期 × 周次对齐、可多份并排。
- **为什么别人做起来难受**：有实现但交互弱（刷选 / 联动 / 与折线的十字线对齐常要另写）。
- **我们怎么做**：时间比例尺 + 热力矩阵都是现成的；排布是纯函数；联动走 `ChartLink`。
  本库路线图已列过这一项，属于顺手补。
- **成本**：低。
- **验收**：跨年 + 跨时区边界（夏令时）不出现重复格或空格；框选返回的是一段日期区间。

## 5. B 档：不进核心库（另开域包的候选）

科学数值向：**等值线 / 相图（`f(x,y)=0`）/ 复变域着色 / 流场与向量场 / 层次聚类树状图**。

不进核心的三个理由：

1. 要新的数值核（marching squares、梯度场、色相映射），属于另一个专业层，会污染核心库；
2. 需求冷门，做完进不了大屏 / 报表 / 表单三条主线；
3. 家族已有先例：**专业语义单独成包，挂在本库之上，本库不知道它存在**（`ice-trading-chart` 即是）。

真要做，照那个形态另开一个包（peer 依赖本库），而不是往 `SeriesType` 里塞。

## 6. 每个候选的固定动作（照 `docs/06-chart-types.md` §8 走，另加两条）

1. `types.ts` 加 `SeriesType` 与选项；`internal.ts` 若引入新场景加 `kind`；
2. `option/normalize.ts` 做点 / 域 / 纯几何（分箱、密度、碰撞后的坐标都放这里）；
3. 组件：`paintPad()` / `rebuildPixels()` / `hitTestIndex()` / `doRender()`（自己 `beginPath()`）/
   需要就 `highlightRectAt()` 或 `drawHoverOverlay()`；
4. `createSeriesComponent` 加 case，两处导出补齐；
5. `syncSeries` 分派 coord；非直角场景隐藏轴与网格；
6. `buildTooltipContent` 加该类型分支；
7. 三类测试：纯函数 / 组件命中 / 引擎集成（真实 `hitTest` + 事件）；
8. 加示例页并进 `scripts/audit-interactions.mjs` 的 `pages`；
9. **补 `ice-chart-dsl` 的 kind 清单**（`CHART_DSL_KINDS` / encoding 通道），否则新类型对 agent 不可见；
10. **回写文档**：`docs/06-chart-types.md` 的类型表、根 `README.md` 的能力清单与「图表类型与写法」、
    `docs/README.md` 若有新专题则登记。

## 7. 不做清单

| 不做 | 原因 |
|---|---|
| 地图 / 地理 | 地理数据 + 投影 + 交互是另一个体量；关系数据走力导向关系图 |
| 3D | 引擎能力之外，另立项目才成立 |
| K 线 / 交易 | `ice-trading-chart` |
| 甘特 / 排期 | `ice-entity-designer` 域包 |
| 建模类图示（ER / 流程 / BPMN / UML / 状态机 / 电力 / 给排水） | `ice-entity-designer` 域包 |
| 追平型形态：蜡烛、漏斗、仪表、词云、和弦、主题河流、旭日、桑基基础形态 | 已有成熟实现，补进去不构成卖点；确实需要时走 `registerSeriesType()` 自定义系列口，自动获得命中 / 悬停 / 提示框 / 图例 / 序列化 |
