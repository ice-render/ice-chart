## 4. 唯一剩下的活：把 `calendar` / `alluvial` 同步进 DSL

`ice-chart-dsl` 目前只到 hexbin（0.6.4）。要做的（与 0.6.4 那轮完全同构）：

1. 分支 `feat/calendar-alluvial-kinds`（该仓纪律：开发分支 → main → 发版，`AGENTS.md` 有正式版）；
2. `src/types.ts`：`CHART_DSL_KINDS` / `CHART_DSL_COMPILED_KINDS` 加 `calendar`、`alluvial`；
   `ChartDslDocument` 加这两个字段（`calendar: { weekStart?, minColor?, maxColor? }`、
   `alluvial: { axes, valueField? }`——**表来自 data/encoding**，与 sankey 的 nodes/links 不同：alluvial 是表的分面，
   所以 `encoding` 用 `x` = 轴1列、`series` = 轴2列…或者更简单：`options.alluvial.axes` + `data` 整表透传）。
   > 具体取哪种写法开工前先定一次，写进该仓 README 的 kind 表。
3. 校验（`src/validate.ts`）：`calendar` 需要一列日期（`encoding.name` 或 `x`）+ 一列数值；
   `alluvial` 需要 `alluvial.axes`（≥2）且这些列都在表里；诊断要可执行（列出可用列名）。
4. 编译：`calendar` → `{ type:'calendar', data:[{date,value}] }`＋`option.calendar` 透传；
   `alluvial` → `{ type:'alluvial' }` + `option.alluvial`。
5. 测试：编译 + 校验各 2~3 条，且**编译产物过一遍 core 的 `normalizeOption`**（该仓铁律）；
   devDependency 与 peerDependency 抬到 `^0.30.16`。
6. `npm run verify` → 合并 main → CHANGELOG `0.6.5` + 版本号 → tag → 双远端 → publish → packument 核验；
   技能卡 `0.2.4`（`npx @skills-hub-ai/cli version ... --changelog "..."` 再 `publish`）。

## 5. 未做 / 已知边界（别当成 bug）

- **面板独立 y 域 / 面板级独立缩放 / 数据驱动 facet**：facet 归 DSL（已在 0.6.4 用 `matrix` 实现）。
